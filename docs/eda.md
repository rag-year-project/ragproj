# Годовой проект: EDA технических инструкций

Воспроизводимый локальный анализ корпуса для поиска ответов по текстам, таблицам и схемам.

- [Корпус: 85 PDF, около 572 МБ](https://drive.google.com/drive/folders/1rfNnKmHLSG3mkVbMDcy040v4phgAtNbp).
- [Чеклист EDA](https://docs.google.com/document/d/1eHSE9a3qsbgTl_w8lufTnGSJUmajbBfG4FGfDq1cbIg/edit).
- Основной ноутбук: `notebooks/main.ipynb`.
- Отчёт: `reports/eda/report.md`.

## Окружение и запуск

Python 3.12+, менеджер пакетов — `uv`; зависимости зафиксированы в `uv.lock`.
Пакеты для анализа выделены в optional-группу `eda`, Ruff — в `dev`.

```powershell
uv sync --extra eda
uv run --extra eda python -m yearproj.eda
uv run --extra eda python scripts/execute_eda_notebook.py
```

В IDE выберите ядро `.venv/Scripts/python.exe`. В ноутбуке `REBUILD=False` читает готовые
результаты и сверяет SHA-256 корпуса; `REBUILD=True` запускает повторное извлечение всех PDF.
Для принудительного пересчёта из CLI:

```powershell
uv run --extra eda python -m yearproj.eda --refresh
```

Извлечение выполняется локально; OCR, обучение и внешние модели не запускаются.
Обработка полного корпуса может занять несколько минут. Старые скрипты предобработки и
BM25 не запускаются и не изменялись.

## Исходные данные

Актуальные PDF лежат в `data/raw/drive_manuals/`; они исключены из Git.
При новом клонировании скачайте содержимое папки Drive и распакуйте PDF непосредственно сюда,
сохранив имена из `data/meta/drive_corpus.json`. Реестр содержит 85 файлов, размеры и ссылки.

Старая папка `data/pdf_manuals/` и её индекс `data/jsons/` сохранены. В ней 21 документ с прежними
номерами; у некоторых файлов номера изменились в Drive. Нельзя смешивать старый `doc_id`
с новым корпусом. Совпавшие по названию модели и размеру PDF были скопированы в актуальный корпус;
последующий анализ использует только `data/raw/drive_manuals/`.

`scripts/download_drive_refs.py` — служебное скачивание по временным ссылкам, полученным
через подключённый Drive. Эти ссылки не являются постоянным способом воспроизведения;
они не хранятся в Git. Для повторного получения PDF используйте исходную папку Drive.

Ручная проверка выявила подмену: `MAN-19_De'Longhi_Magnifica_S_(ECAM_22.110).pdf`
содержит рекламную веб-страницу, а не руководство (2 страницы).
Решение `exclude`, причина и SHA-256 сохранены в `data/meta/document_review.csv`.
Сводные доли пока описывают исходный корпус, включая этот файл; остальные 84 PDF
не объявляются прошедшими сплошную ручную проверку. Перед бенчмарком файл следует заменить.
После обновления ручных решений можно пересобрать отчёт без извлечения PDF:

```powershell
uv run --extra eda python scripts/update_eda_review.py
```

Все номера страниц — **физические номера PDF с 1**, а не печатная нумерация инструкции.
`char_count` учитывает пробелы: на некоторых арабских страницах извлечение с `sort=True`
создаёт сотни тысяч пробелов выравнивания. Для сравнения объёма текста используйте
`nonspace_char_count` и `whitespace_share`; гистограмма построена по `log10(nonspace_char_count+1)`.
Категории `*_candidate` — эвристики. Векторная графика может быть схемой, логотипом или рамкой;
автоматические результаты не дают точного числа семантических схем. Отсутствие текстового слоя
также не доказывает, что страница является сканом. Доли используют число успешно прочитанных
страниц; ошибки и полнота корпуса вынесены в отчёт.

В `page_review_queue.csv` есть одна случайная страница каждого PDF плюс редкие категории
(seed=42). Такая очередь полезна для поиска ошибок, но не подходит для несмещённой оценки долей.
Поля `has_picture`, `has_table`, `has_schematic`, `text_only`, `is_scan` заполняются как
`yes/no/unknown`; `language_reviewed` — код языка или `mixed/unknown`. Сохраняйте ручную разметку
**отдельной копией**, поскольку очередь пересоздаётся. Для точных количеств размечайте весь корпус,
а для статистической оценки заранее зафиксируйте случайную выборку и её объём.

## Разметка вопросов и главный вывод EDA

`data/meta/benchmark_qa.csv` — пустой шаблон реальных QA, а не искусственно созданный бенчмарк.
До появления разметки распределение типов вопросов и доля визуально зависимых ответов
**не определены**. Наличие картинки на странице не заменяет эту оценку.

Для каждого вопроса заполните:

1. `q_id`: уникальный ID; `question`: вопрос; `doc_id`: точное имя PDF без `.pdf`.
2. `target_page`: физическая страница PDF с 1; `answer`: проверенный ответ.
3. `question_type`: `text`, `table`, `schematic`, `mixed` или `unknown`.
4. `requires_visual`: `yes`, если PDF подтверждает ответ, а извлечённого текста страницы
   недостаточно; `no`, если текста достаточно; `unknown`, если проверка не завершена.
5. `evidence_notes`: объяснение со ссылкой на элемент страницы. Отдельно укажите, связана ли
   проблема с OCR/порядком извлечения или со пространственным смыслом схемы.
6. `family_group` и `split`: заполняйте только после проверки семейств моделей/дубликатов.

Сначала опишите целевой сценарий и план отбора вопросов. Не балансируйте типы искусственно,
если хотите оценить их естественные доли. При разметке несколькими людьми часть вопросов
проверьте независимо и разберите расхождения. Не используйте тестовые вопросы для настройки.

Если всего `N` вопросов, из них проверено `n`, а `v` требуют визуального анализа, отчёт покажет
`v/n` для проверенных и границы `[v/N, (v+N-n)/N]` для всей выборки.
`unknown` не считается отрицательным ответом. Wilson 95% выводится условно: он предполагает
независимую случайную выборку, а вопросы одной инструкции могут быть зависимыми.
Без описанного отбора результат характеризует размеченную выборку, а не весь будущий трафик.

Все страницы и вопросы одного семейства/дубликата должны попадать в один train/dev/test.
Пока разбиение не выполнено. Метрики retrieval/accuracy в EDA не рассчитываются.

## Проверки

```powershell
uv run --extra eda ruff check src/yearproj/eda.py scripts tests
uv run --extra eda python -m unittest discover -s tests -v
uv run --extra eda python scripts/execute_eda_notebook.py
```

Тесты проверяют площадь перекрывающихся изображений, отличие пустой страницы от растрового
скана, нумерацию PDF, валидацию QA и знаменатели долей с неизвестными метками.
Скрипт выполнения ноутбука использует новое ядро Python текущего окружения и сохраняет outputs.
